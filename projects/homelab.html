~/projects/homelab

The homelab.

One Proxmox box doing more than it probably should, plus a NAS, plus a small pool I solo-mine to. Built to be useful, not impressive.

#Layout

One Proxmox host carries the whole thing. On top of it:

  • A few Ubuntu server VMs for things that want a real OS to themselves.
  • A TrueNAS VM that handles storage (with the disks passed through directly, not virtualized).
  • A handful of LXC containers for lighter services where a full VM would be overkill.
  • A Docker host running inside one of the Ubuntu VMs, with Portainer in front so I don't lose track of what's deployed where.

The reasoning is mostly about blast radius. If I break a container, I only break a container. If I break the Docker VM, the Proxmox host is still fine. If TrueNAS goes sideways, the VMs on the other disks keep humming.

#Running today

A non-exhaustive list of what's currently up:

  • Reverse proxy fronting the services that get exposed publicly.
  • Dashboards and monitoring (you start running services, you start needing to know when they stop).
  • Media services for the household and family.
  • A Bitcoin full node, plus a self-hosted pool I solo-mine to. More on that here.
  • Backups for the things that would hurt to lose.
  • A pile of smaller stuff: DNS, ad/tracker blocking, a few utilities, the usual sysadmin furniture.

#Rules I try to follow

Not formal, just things I've learned by doing the opposite first:

  • Don't deploy anything I haven't at least skimmed the docs for.
  • If a service can be private, it stays private.
  • Backups aren't backups until they've been restored at least once.
  • If I can't explain why a container is running, it shouldn't be running.

#What's next

Right now: cleaning up local DNS to block trackers across the whole network without breaking the handful of services that get unreasonably picky about it. Apparently Amazon is the hard part.

After that: documenting more of this in notes so I stop relying on memory.
